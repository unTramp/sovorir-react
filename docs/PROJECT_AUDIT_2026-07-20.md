# Sovorir React - полный аудит

Дата: 20 июля 2026

## Как проведен аудит

Проверены архитектура и модель контента, UX мобильного PWA, админ-конструктор,
доступность, безопасность конфигурации, тесты и production-сборка. Подход
соответствует шаблонам `ARCHITECT_AUDIT`, `PRODUCT_REVIEW`, `UI_UX_REVIEW` и
`SAFE_IMPLEMENTATION` из `pet-match/docs/ai`: ниже только подтвержденные
проблемы, без изменений кода.

Проверки:

- `npm run lint` - не проходит: 10 ошибок.
- `npm test` - 167 из 168 тестов проходят; 1 тест не проходит.
- `npm run suite:build` - успешно собирает ученическое PWA и админку.
- Локальный сервер отвечает `HTTP 200` на `http://127.0.0.1:4175/`.

Ограничение аудита: визуальная проверка в реальном браузере и на физических
телефонах не выполнялась. Она нужна перед релизом после исправления P1.

## Краткий вывод

Это уже не набросок: есть React/Vite PWA, роли, ученический кабинет, отдельная
админка, API/mock-слой, offline-кеширование, секции и блоки урока. Сборка
проходит, а форма контентного конструктора заметно лучше, чем описано в старой
документации.

Главная проблема не в количестве экранов, а в разрыве между ними. Данные
словаря и практики остаются статичными, а семантическая модель урока еще
частично хранится и обрабатывается как legacy-модель. Поэтому CSV нельзя
безопасно просто "залить" в текущие файлы: он не попадет в словарь, карточки,
повторение и квизы как единый проверяемый контент.

## P0 - критическое

Подтвержденных P0 нет.

- Секреты в `.env` и `.env.local` не отслеживаются Git, а клиентский код не
  обращается к `OPENAI_API_KEY` или `ANTHROPIC_API_KEY`.
- Production-сборка обеих частей проходит.

Это не означает готовность к релизу: P1 ниже нужно закрыть до публикации
нового учебного контента.

## P1 - важное, закрыть до масштабирования курса

### 1. Качество сборки не является надежным стоп-краном

Файлы: `src/components/center/HomeView.tsx:33-54`,
`src/components/center/StatisticsView.tsx:65-68`,
`src/components/practice/PronunciationTrainer.tsx:32-45`.

Проблема: ESLint фиксирует 10 ошибок. В `HomeView` часть hooks вызывается после
условного `return`; при смене роли в уже смонтированном дереве React может
получить другой порядок hooks. В статистике в render вызывается `Date.now()`,
а тренажер произношения синхронно меняет state внутри эффектов.

Риск: непредсказуемый экран после авторизации/переключения роли, лишние
рендеры, невозможность использовать lint как release gate.

Сложность: низкая. Польза: высокая.

Рекомендация: сначала исправить эти 10 ошибок, затем сделать `lint`, `test` и
`suite:build` обязательными в CI. Не смешивать это с редизайном или импортом
CSV.

### 2. Один тест админ-конструктора красный, а warnings скрывают асинхронные ошибки

Файл: `src/test/components/AdminLessonBuilderView.test.tsx:43-62`.

Проблема: тест ждет поле `Название урока`, но остается на экране загрузки.
Также `LessonView` и `HomeView` выводят предупреждения React `act(...)`; в
проверке роли преподавателя зафиксирован рендер с `queue` без гарантированного
массива.

Риск: редактор урока и его загрузка не имеют надежно проверяемого контракта;
регрессии легко попадут в ручное тестирование.

Сложность: средняя. Польза: высокая.

Рекомендация: изолировать репозиторий конструктора в тесте, дождаться окончания
загрузки корректным mock-ом, исправить `act` warnings и добавить проверки:
ошибка загрузки, пустой список уроков, сохранение draft/publish, preview.

### 3. Аудио сейчас блокирует именно тот сценарий, который нужен продукту

Файлы: `src/types/lessonContent.ts:49-62`,
`src/components/lesson/BlockRenderer.tsx:17-51`,
`src/components/audio/VoiceBubble.tsx:13-87`,
`src/components/admin/builder/validation.ts:20-30`,
`src/components/admin/builder/BlockTypedFields.tsx:281-315`.

Проблема: `teacherBubble` и `studentBubble` требуют `audioSrc`, а валидатор
запрещает публикацию бабла без ссылки на аудио. Рендерер всегда передает его в
аудиоплеер. У student bubble текст вообще не показывается, он заменен плеером.

Риск: нельзя использовать любимый формат урока - сообщения преподавателя и
ученика - когда аудио пока недоступно. Пустой или нерабочий плеер разрушает
доверие к интерфейсу.

Сложность: средняя. Польза: очень высокая.

Рекомендация: сделать аудио необязательным для обоих bubble-блоков. Один
компонент бабла должен показывать текст всегда, а плеер - только при наличии
валидного источника. В админке поле аудио обозначить как необязательное, а
валидацию публиковать по тексту и имени. `studentBubble` стоит вывести из
reserved в активный тип для текстовых мини-диалогов; запись и оценку
произношения оставить выключенными до появления аудио.

### 4. CSV не имеет продуктового пути в приложение

Файлы: `src/data/dictionary.ts`, `src/components/center/DictionaryView.tsx:1-24`,
`src/components/center/PracticeView.tsx:1-47`,
`src/lib/contentRepository.ts:136-148`.

Проблема: исходный CSV содержит 3 306 физических строк и разнородные учебные
материалы, но словарь приложения - статический demo-набор. Dictionary и
Practice импортируют его напрямую; даже API repository возвращает тот же
статический массив.

Риск: импорт в backend или admin builder не изменит словарь и повторение.
При прямой подстановке большого CSV интерфейс будет рендерить все карточки
сразу, без проверки качества, тем, уровня, статуса и связи с уроками.

Сложность: средняя. Польза: очень высокая.

Рекомендация: создать отдельный vocabulary pipeline, а не расширять
`dictionary.ts` вручную. Минимальная сущность: `id`, `sourceRow`, `armenian`,
`transcription`, `translation`, `example`, `exampleTranslation`, `topic`,
`level`, `partOfSpeech`, `status`, `lessonIds`, `reviewStatus`. Сначала
импортировать CSV в staging с отчетом о пустых/сомнительных строках и дублях,
после проверки преподавателем публиковать записи. Затем читать единый
`VocabularyRepository` в Dictionary, Practice, lesson builder и генераторе
квизов.

### 5. Семантическая модель урока еще не сквозная

Файлы: `src/lib/semanticContent.ts:1-192`,
`src/types/lessonContent.ts:1-87`, `src/lib/quizGenerator.ts:20-22`,
`docs/content-model.md:228-244`.

Проблема: автор видит `teacherBubble`, `phraseCard`, `readingText`, но внутри
они частично преобразуются в legacy `audio`, `phrase`, `text`. В частности,
генератор квиза извлекает только `phrase`, а не `phraseCard`.

Риск: контент, созданный в новом типе, может отображаться на уроке, но не
попасть в квиз. Это особенно опасно при импорте CSV, когда часть материала
создается автоматически.

Сложность: средняя. Польза: высокая.

Рекомендация: выбрать целевой контракт `ContentBlock` и завершить миграцию
одним этапом: семантические типы хранятся, валидируются, отдаются API и
обрабатываются генератором. До этого добавить совместимость в quiz generator
для `phrase` и `phraseCard` и покрыть оба типа тестами.

### 6. Словарь обещает действие, которое сейчас не работает

Файл: `src/components/dictionary/DictCard.tsx:19-24`.

Проблема: кнопка "Прослушать" визуально активна, имеет `aria-label`, но не
имеет обработчика.

Риск: пользователь нажимает на ключевое действие изучения языка и ничего не
происходит; это воспринимается как поломка.

Сложность: низкая. Польза: высокая.

Рекомендация: пока аудио нет, убрать кнопку из карточек полностью. Позже
показывать ее только при `audioSrc`, как уже делает `PhraseCard`.

### 7. Ошибки загрузки уроков не становятся состоянием интерфейса

Файл: `src/stores/useLessonSectionsStore.ts:15-20`.

Проблема: запрос секций запускается через `void ... then(...)` без `catch`,
loading/error/retry состояния и защиты от ответа устаревшего запроса. Перезагрузка
срабатывает при фокусе, восстановлении вкладки и синхронизации админки.

Риск: в PWA с плохой сетью возможна необработанная ошибка или устаревший
контент без объяснения пользователю.

Сложность: средняя. Польза: высокая.

Рекомендация: привести store к контракту catalog store: `isLoading`, `error`,
последний успешный результат, retry и защита от race condition. Экран урока
должен показывать понятную ошибку и кнопку повтора, сохраняя кешированный урок.

## P2 - полезное после P1

### 1. Удалить голубую тему как параллельную визуальную систему, а не баблы

Файл: `src/styles/globals.css:4-117`.

Проблема: базовая палитра терракотовая/оливковая, но student bubble, waveform и
progress используют самостоятельную голубую палитру (`--color-student-*`). Это
делает приложение одновременно теплым курсом и синим мессенджером.

Риск: визуальная несобранность, слабее ощущение авторского продукта.

Сложность: низкая-средняя. Польза: высокая.

Рекомендация: сохранить форму и логику пузырей, но заменить голубой student
слой на приглушенный шалфейный/оливковый нейтральный набор, уже согласованный с
`--color-done`. Вынести все цвета сообщений в семантические токены и удалить
устаревшие blue tokens. Это одна из первых UI-итераций после P1, отдельным
небольшим PR.

### 2. Доступность интерактивных карточек неполная

Файлы: `src/components/practice/FlashcardCard.tsx:13`,
`src/components/center/TeacherDashboardView.tsx:47-56`.

Проблема: кликабельные `div` не имеют нативной клавиатурной семантики. В
teacher dashboard `queue.length` предполагается массивом и может упасть при
неинициализированном состоянии, что видно в test output.

Риск: недоступность с клавиатуры, слабее поддержка screen reader, хрупкий
teacher flow.

Сложность: низкая. Польза: средняя.

Рекомендация: использовать `<button>` для действий или добавить корректные
role/tabIndex/keyboard handlers; гарантировать `queue = []` в состоянии и
добавить edge-case test.

### 3. Документация расходится с кодом

Файлы: `README.md`, `docs/admin-panel-current-functionality.md:98-109`,
`src/components/admin/builder/BlockTypedFields.tsx`.

Проблема: README остался от Vite template. Документ админки говорит, что блоки
редактируются только JSON, хотя в коде уже есть типизированные поля для
heading, text, phrase, rule, quiz и teacher bubble.

Риск: неверные решения при развитии продукта и долгий onboarding.

Сложность: низкая. Польза: средняя.

Рекомендация: написать короткий Sovorir README: запуск, mock/live, роли,
структура, команды проверки, местоположение content model. Обновить документ
админки по фактическому UI и явно описать, какие функции являются MVP.

### 4. Нет автоматической проверки основного пользовательского пути

Проблема: есть 168 unit/component tests, но нет E2E проверки: login -> home ->
lesson -> completion -> practice, а также teacher/admin -> builder -> preview.

Риск: основные связи между роутингом, хранилищами, PWA и API остаются ручной
проверкой.

Сложность: средняя. Польза: средняя-высокая.

Рекомендация: после стабилизации unit tests добавить 4-6 Playwright сценариев
на desktop и mobile viewport; проверять также длинные армянские фразы,
offline-кеш и отсутствие горизонтального скролла.

### 5. Админка пока не масштабируется до управления курсом

Файлы: `docs/admin-panel-current-functionality.md:19-27`,
`src/components/center/AdminLessonBuilderView.tsx`.

Проблема: рабочая админка сфокусирована на одном уроке, без каталога курса,
словаря, импорта, версии, review workflow и медиа-библиотеки.

Риск: ручная публикация 10-12 уроков и тысяч слов будет непредсказуемой.

Сложность: высокая. Польза: высокая после P1.

Рекомендация: не строить универсальную CMS. Следующий узкий шаг: каталог
уроков + словарь/staging + "проверить и опубликовать". Только после этого
нужны версии, медиа и аналитика.

## Что уже хорошо и не нужно ломать

- Разделение на ученическое PWA и отдельную админку удачно для текущего MVP.
- Роли, маршруты, API/mock repository и content model уже задают правильную
  основу.
- PWA manifest, install flow и production service worker собраны корректно.
- Урок собран из секций и блоков, а не из одной гигантской страницы.
- `PhraseCard` уже проектируется с необязательным `audioSrc`: это верный
  ориентир для баблов.
- Формат сообщений преподавателя - сильный дидактический и визуальный паттерн;
  его следует расширять, а не заменять карточками.

## Рекомендованный курс действий

### Этап 1. Стабилизация, 1 короткий спринт

1. Исправить 10 lint ошибок.
2. Починить один падающий тест и warnings `act`.
3. Добавить CI gate: lint, test, suite:build.
4. Убрать неработающие audio кнопки и сделать bubble text-only.

Критерий готовности: все три команды зеленые; ученический и teacher flow не
падают при пустых/загружаемых данных.

### Этап 2. Контент без аудио, 1 спринт

1. Утвердить `teacherBubble` и `studentBubble` с optional `audioSrc`.
2. Завершить совместимость semantic/legacy типов в renderer, validation,
repository и quiz generator.
3. Подготовить 2 эталонных урока из существующих материалов: greetings и
базовый диалог. Они станут шаблоном для импорта, UX и QA.

Критерий готовности: урок с баблами и phrase cards публикуется без аудио,
проходит квиз и корректно открывается из preview.

### Этап 3. CSV vocabulary pipeline, 1-2 спринта

1. Зафиксировать словарную схему и правила нормализации транскрипции.
2. Написать import preview с отчетом: строки прочитаны, пропущены, дубли,
неполные пары, нераспознанные заголовки/диалоги.
3. Проверить и разметить данные преподавателем: тема, уровень, тип, lesson.
4. Подключить VocabularyRepository к dictionary, flashcards и quiz generator.
5. Добавить поиск на сервере, пагинацию/виртуализацию для большого словаря.

Критерий готовности: опубликованная запись CSV в одном месте появляется в
словаре, в нужном уроке, в карточках повторения и в тесте.

### Этап 4. Единый дизайн и обучение, параллельно с этапом 3

1. Заменить blue student tokens на теплый шалфейный набор, оставив баблы.
2. Убрать декоративные emoji из рабочих контролов, где есть существующие icons.
3. Сделать 4-6 E2E сценариев и визуальную проверку мобильных экранов.
4. Оставить аудио, запись и AI pronunciation как выключенные возможности, а не
как полуработающие элементы интерфейса.

## Top 5 улучшений по ROI

1. Text-first баблы без обязательного аудио.
2. Починить lint/test и сделать их CI gate.
3. Ввести VocabularyRepository и staging-импорт CSV.
4. Довести semantic blocks до квизов и API без legacy-рассинхронизации.
5. Заменить голубую student-тему на согласованные теплые токены, сохранив
   bubbles.

## Решение по продукту

Рекомендуемый вариант: развивать существующее PWA, а не делать отдельное новое
приложение или набор PDF. В нем уже есть нужные для регулярной практики
механики: уроки, словарь, интервальные карточки, роли и админ-путь. PDF может
быть только дополнительным экспортом "конспект урока" после появления
проверенного контентного источника; он не должен быть первичным способом
освоения материалов.
